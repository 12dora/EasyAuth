# ADR-004：EA-AUD-030/032/033 旧兼容形态清理

## 状态

已接受

## 日期

2026-07-27

## 背景

EA-AUD-030、EA-AUD-032 与 EA-AUD-033 指出后端、前端和 SDK 中仍存在已废弃抽象、旧入口、重复 facade 与未使用导出。项目尚未上线，且没有提供外部旧契约白名单，因此这些形态不应继续作为正式产品契约存在。

旧形态包括未作用域目录引用、通知收件人的旧唯一约束、SDK 暴露的钉钉前缀常量、静态 token 独立 facade、CRM 试点种子命令，以及已确认没有调用方的分页、模板、状态和类型导出。

## 决策

1. 目录引用只接受服务端返回的 opaque ref 或带完整 source/corp 的 scoped ref。裸 Authentik 用户引用保留为当前权威用户引用输入；未作用域 `dt:<id>` 与原始部门 ID 不再作为目录或通知收件人兼容输入。
2. 通知收件人只按 `(message, source_slug, corp_id, dingtalk_user_id)` 形成 canonical 唯一性。不再保留缺少完整 source/corp 的旧形态唯一约束。
3. SDK 不再导出 `DINGTALK_REF_PREFIX`。下游必须透传目录 API 返回的 `user_ref`、`department_ref` 与主管引用，不得自行拼接。
4. 静态 token 生命周期归并到 `AppCredentialService`。删除 `StaticTokenService`、`StaticTokenIssue` 与 `AppStaticToken` facade，API、控制台和测试直接使用凭据服务与 `IssuedStaticToken`。
5. 删除 CRM 试点种子命令与 fixture。试点数据不作为产品初始化路径保留。
6. 删除已确认无调用方的后端函数、常量、旧模板入口、前端类型、状态分支和多余导出。若后续需要同名能力，必须按当前 domain/API 重新建模，不得恢复旧兼容层。

## 后果

- 发送未作用域 `dt:<id>`、原始部门 ID 或自行拼接的目录引用会快速失败或记录逐收件人错误，调用方必须刷新目录缓存并使用服务端引用。
- 通知数据库迁移会移除旧形态唯一约束；历史迁移文件只保留数据库演进事实，不再代表当前契约。
- 静态 token 行为保持原能力边界，但公开入口收敛到凭据服务，减少 API、控制台和测试中的双轨语义。
- 前端与 SDK 的公共导出面变窄，避免未使用符号被误认为稳定契约。

# EasyAuth 第一性整改路线图

审计日期：2026-07-27
依据：[权威审计综述](README.md)
性质：整改建议，不包含实现

## 1. 目标与边界

整改目标不是逐条修补报告中的局部症状，而是恢复以下唯一事实链：

`schema → domain → API → frontend → tests → docs`

每个变更集必须同时检查这六层。若某层不受影响，也要在变更说明中明确证明，而不是默认遗漏。
运行与发布层还必须证明迁移、后台任务、构建产物、服务重启和真实 HTTP 响应使用了新代码。

本路线图只推荐实施顺序和验收证据，不修改源码、测试、配置或运行环境。

## 2. 不可妥协的实施原则

### 2.1 不建立兼容垫片

项目尚未上线，错误模型应一次性移除。禁止：

- 新旧字段并存、双写或读取时“优先新字段、回退旧字段”；
- 缺少修订时读取最新授权或当前模板；
- 非法枚举显示为正常“未知状态”并继续渲染业务行；
- 畸形响应转换为空列表、空对象、默认分页或成功；
- 通过 `.first()`、默认值、首项优先或静默截断解决歧义；
- 保留旧路由、旧类型、旧别名或转发模块以减少调用方修改；
- 将依赖失败、部分失败或没有实际变更降级为任务成功。

唯一允许的临时兼容是已证明的外部契约或受控一次性迁移窗口；必须同时记录调用方、截止时间、
移除条件、拒绝后的错误码和负责人员。兼容窗口不得进入长期领域模型。

### 2.2 先定义事实，再修改接口

每个变更集先写清：

1. 聚合根、状态、修订、幂等身份和前置条件；
2. 数据库允许和拒绝的状态真值表；
3. 命令成功、冲突、部分完成和依赖失败的机器语义；
4. 哪些读模型会被命令改变；
5. 用户在每种状态下能看到和执行的动作；
6. 安全审计、运维恢复和数据保留要求。

没有这些事实，不进入 API 或前端实现。

### 2.3 非法历史数据必须显式阻断

增加约束或重建迁移前，先运行只读扫描。发现非法行时：

- 迁移快速失败并输出安全的行数、主键范围或诊断编号；
- 由独立、显式、可审计的修复流程处理；
- 不在迁移中静默删除、填默认值或重绑到“最可能”的父对象；
- 数据修复完成后再施加约束并复跑反例。

### 2.4 每一波都要形成可发布证据

实际实施时，每个独立变更完成后按项目规则提交 commit。任何影响 Django、模板、React 构建、
Vite manifest 或页面响应的修改都必须：

1. 后端检查、迁移检查、相关测试通过；
2. 前端测试、类型检查和生产构建通过；
3. 重启当前 Django 开发服务；
4. 用目标 URL 的真实 HTTP 响应或浏览器页面验证新代码已加载；
5. 记录命令、提交 SHA、工具版本和验证时间。

## 3. 依赖顺序

整改按以下依赖推进：

1. 先封闭不可信生产路径并确认数据、密钥和外部消费者；
2. 建立最小可信质量门禁，修复特权会话撤权；
3. 修复异步任务的租约、fencing、恢复与完成语义；
4. 重建授权修订、模板修订、状态机和数据库关系；
5. 在新领域事实之上重建 API、能力模型、前端状态和错误契约；
6. 收紧出站网络、秘密和保留策略；
7. 用真实规模与 PostgreSQL 查询计划治理性能和运维；
8. 修复国际化、反馈、响应式和无障碍；
9. 最后删除死代码、旧兼容形态并拆分架构热点。

后续波次不得为了提前上线而绕过前置波次。例如，在授权申请尚未绑定修订前，不应先给门户增加
完整 `change`、`revoke`、`renew` 操作；否则只是让更多用户进入错误并发语义。

## 4. 第 0 波：止损、清点与决策

关联登记项：`EA-AUD-001`、`EA-AUD-023`、`EA-AUD-033`、`EA-AUD-034`

### 4.1 变更集

- 将 `docker-compose.deploy.yml` 明确标记为不可公开暴露、不可作为生产部署输入；在唯一生产
  路径完成前停止新增使用。
- 只读清点现有 SQLite、备份、环境变量键、服务账号权限和需要迁移的数据集，不读取或输出秘密
  明文。
- 确认本地试点/验收数据是否需要保留，并选择“全新空库”或“显式数据保持迁移”，不能模糊处理。
- 清点 SDK 发布、下游仓库、请求日志和人工运维记录，决定 legacy 目录引用、静态 token facade、
  `DINGTALK_REF_PREFIX` 和 CRM seed 是否存在正式外部契约。
- 决定授权 `version` 是可变聚合 `revision` 还是不可变历史修订；决定 Django Admin、单因素
  本地超管和全部 App 目录的正式安全政策。
- 形成 Stream、Webhook、审计、目录画像和备份的保留政策草案。

### 4.2 分层产物

| 层 | 必须形成的产物 |
| --- | --- |
| schema | 数据集、现存行数、坏数据扫描项、迁移保留决策 |
| domain | 授权修订语义、特权平面、legacy 契约和保留边界的明确决定 |
| API | 外部消费者与当前公开输入/输出清单 |
| frontend | 当前可达占位入口、legacy 状态和公开能力清单 |
| tests | 当前命令、skip、测试数据库和外部依赖的基线记录 |
| docs | 中文决策记录、数据迁移前置条件、legacy 白名单或明确无白名单结论 |

### 4.3 完成证据

- 生产与开发部署入口不会被同一命令或同一文件名混淆；
- 每个待决策项都有明确结论、负责人和日期；
- 数据保留或清空均有人工确认，不存在“未上线所以可静默删除”的默认；
- 外部契约不存在时，文档明确允许后续直接删除兼容形态；
- 没有执行任何实际删库、轮换或业务迁移。

## 5. 第 1 波：生产信任根、特权撤权与最小质量门禁

关联登记项：`EA-AUD-001`—`EA-AUD-003`、`EA-AUD-017`、`EA-AUD-022`、`EA-AUD-024`、
`EA-AUD-031`

### 5.1 变更集 A：唯一生产部署

**schema 与运行**

- 生产只使用 PostgreSQL；移除 SQLite bind mount、`touch db.sqlite3` 和多进程共享文件库。
- 强制 `DEBUG=0`、独立高熵 Django 签名密钥和字段加密密钥，缺失或命中开发值立即拒绝启动。
- 使用正式 WSGI/ASGI 进程，删除生产路径中的 `runserver` 和源码 bind mount。
- 生产只部署通过质量门禁、带 provenance/SBOM/Cosign 的不可变镜像 digest。
- 按 web、默认 worker、Webhook worker、通知 worker、beat、stream 的实际职责拆分 secrets；
  root/`NET_ADMIN` 只保留给经过证明必须拥有的最小进程。

**受控迁移**

- Django `SECRET_KEY` 轮换必须使现有会话全部失效。
- 字段加密密钥只允许一次性“旧密钥解密—新密钥重加密—逐行验证—销毁旧密钥”流程；不得形成
  双密钥长期读取。
- SQLite 到 PostgreSQL 迁移必须核对行数、外键、唯一约束、状态形状和关键授权事实。

### 5.2 变更集 B：唯一特权会话事实

**领域层**

- 本地管理员请求期身份只由 `current_local_admin()` 或新建的唯一权威解析器决定。
- OIDC 高权限建立服务端可撤销 epoch 或权威短时判定；权威状态不可用时，高权限请求失败关闭。
- OIDC callback 在建立 session 前校验本地 `UserMirror` 状态；停用主体必须在认证边界直接失败，
  不能先返回成功再由门户清 session。
- TOTP 与 Passkey 的 begin/complete 使用同一权威二次验证节流策略；失败累计、冷却和解锁语义
  由一个领域状态机决定。
- 明确普通 Console 访问、App owner 和系统管理员三种身份的会话与撤权语义。

**API 与前端**

- 所有控制台 API 使用同一 actor 构造；版本或标志失配时清除完整认证 session 并返回统一 401。
- 壳层把并发 401 合并为一次重新登录状态，保留安全的内部 `next`，不让各请求重复 toast。
- 安全设置成功后页面状态、会话撤权提示和重新登录动作必须一致。

### 5.3 变更集 C：最小可信门禁

- 建立主后端、PostgreSQL、SDK/FastAPI、Ruff、BasedPyright、前端类型/测试/构建和最小浏览器
  冒烟作业；镜像发布依赖全部作业成功。
- PostgreSQL lane 使用独立临时数据库并断言 vendor；SQLite lane 不读取遗留 `DATABASE_URL`。
- 删除控制台 `Client.login` autouse 桥和通知 autouse 造数，改用显式生产会话 fixture 和业务
  factory。
- FastAPI 全功能 lane 不允许整模块 skip；最小依赖 lane 只证明核心 SDK 可导入。

### 5.4 完成证据

- 生产 settings 在 `DEBUG=1`、开发密钥、SQLite 或缺少必需 secret 时启动失败；
- 部署清单能由运行镜像 digest 反查签名、SBOM 和通过的质量作业；
- 改密、TOTP 启停、Passkey 增删、账号停用再启用、OIDC 撤组后，旧会话访问 `/console/`
  和高权限 API 均失败；
- 停用 `UserMirror` 的 OIDC callback 不创建任何已认证 session；Passkey begin/complete 与
  TOTP 共享节流预算，绕过其中任一入口的测试失败；
- 只有 Django `_auth_user_id`、没有权威 EasyAuth 会话的请求返回 401；
- PostgreSQL、SDK/FastAPI 和前端作业均实际收集预期测试，不依赖未白名单 skip；
- 修改运行页面后完成前后端重建、Django 重启，并以真实 `/health/`、`/console/`、
  `/auth/local/` HTTP 响应验证新配置和静态资源。

## 6. 第 2 波：可恢复异步协议与外部副作用 fencing

关联登记项：`EA-AUD-004`—`EA-AUD-006`、`EA-AUD-015`、`EA-AUD-016`

### 6.1 领域和 schema

- 为 Webhook、连接器、目录代次、通知对账、Stream 和 Outbox 分别写出状态真值表。
- 所有 claim 必须持久化唯一租约令牌、generation、到期时间、尝试次数和最后类型化错误。
- 任务 hard limit、租约、批次 deadline 和外部调用预算由同一配置事实源推导。
- 引入权威 watchdog：扫描过期租约，按实体 ID、generation 和幂等事件键恢复；恢复不是把状态
  重置为空，而是显式产生下一次可审计尝试。
- 所有外部副作用前比较并续租，包括扩权、撤组、封禁、解封、创建和删除；失去租约立即停止。

### 6.2 domain 与任务

- 任务返回成功必须等价于领域动作完成或明确进入可恢复排队状态。
- 离职禁号、通知对账、目录同步和健康检查不得把未配置、依赖错误、分页上限或部分失败转成空结果
  或成功。
- 目录 generation 只有全部必需事实完成后才能推进；若产品允许部分同步，必须建立一等
  `incomplete` 状态和同 generation 定向重试。
- Webhook 的未预期异常、soft/hard timeout、数据库瞬时错误和 worker 丢失都要留下可恢复事实。

### 6.3 API 与 frontend

- 管理 API 暴露稳定的 `queued`、`running`、`incomplete`、`failed`、`recovery_pending` 等机器
  状态，不返回含混布尔值或成功字符串。
- 前端区分首次失败、旧数据刷新失败、任务合并、真正入队、部分完成和最终失败；后台轮询失败只在
  区块内标记陈旧，不周期性弹 toast。
- 运维页提供按权威状态允许的重试动作，不允许任意状态被人工“重投成功”。

### 6.4 tests 与 docs

- PostgreSQL 多连接和多 worker 测试覆盖租约接管、旧 worker fencing、watchdog、重复消息、
  worker 中止、broker 发布失败和幂等重投。
- 使用可控 fake 外部系统记录每次副作用，断言失去租约的 worker 不再产生任何写入。
- 中文状态机文档记录状态、令牌、时间限制、重试、人工处置和告警条件。

### 6.5 完成证据

- 在认领后任意一步杀死 worker，过期租约都能由 watchdog 恢复且不会重复完成外部动作；
- 让任务超过旧租约时，新旧 worker 不会并发对同一外部主体写入；
- Authentik 未配置、分页耗尽、通知 provider 失败和目录单用户失败均留下失败事实并进入重试或
  人工处置，不返回成功；
- 健康 API 能看到 connectors 和不完整 generation，不把 `{}` 或缺字段响应标为健康；
- beat 名称、路由队列、worker `--queues`、task 名和健康心跳由参数化测试逐项对齐。

## 7. 第 3 波：授权修订、模板修订和数据库不变量

关联登记项：`EA-AUD-007`—`EA-AUD-014`、`EA-AUD-023`、`EA-AUD-034`

### 7.1 变更集 A：授权修订与申请前置条件

- 根据第 0 波决定，采用唯一模型：
  - 若需审计回放，使用稳定 `AccessGrant` 聚合根和不可变 `AccessGrantRevision`/成员快照；
  - 若只需当前事实，将 `version` 明确定义为 `revision`，历史事实由不可变事件承担。
- `change`、`revoke`、`renew` 必须保存基础授权主键和修订，并纳入幂等摘要。
- 提交校验、审批展示和最终落地共用一份“当前有效授权成员”领域查询；到期过滤和成员集合不能
  在三个阶段各自实现。
- 审批展示、审计事件和最终执行使用同一冻结快照；修订不一致进入明确“申请已过期”，绝不回退
  到最新授权。

### 7.2 变更集 B：不可变模板修订

- 模板编辑创建新 `OnboardingTemplateRevision` 及不可变项，不再删除重建已被计划引用的内容。
- `TransferPlan` 绑定精确模板修订和冻结差异；确认时按绑定修订执行。
- 新修订出现不自动使旧计划失效；只有绑定修订停用或计划前置条件失效才返回冲突。

### 7.3 变更集 C：数据库可执行不变量

- WebAuthn 计数使用锁定后验证或带旧值/单调条件的原子更新，并增加非负约束。
- 为申请、通知、Outbox、审批回调和 Stream 分别建立状态真值表及 `CheckConstraint`。
- 将跨 App 关系改为数据库可表达的复合键/外键，或消除重复 `app_id` 来源；不能读取时纠正。
- 把 `ManagedScopePolicy` 拆成真实外键表；规范化目录身份绑定并建立来源作用域唯一约束。
- 统一 `UserMirror` 保留语义，相关业务事实使用 `PROTECT`/`RESTRICT` 或明确数据库保护。
- 通知幂等规范化值对象同时驱动校验、哈希和持久化；汇总计数以明细为事实源或在同一事务维护。

### 7.4 API 与 frontend

- API 返回修订令牌、冻结快照和明确冲突 code；不接受缺修订旧 payload。
- 门户和控制台展示“基于哪个修订审批”，前置条件失效时要求重新审阅。
- 模板编辑、申请审核、交接确认和通知详情同步更新，不显示不可重建的旧版本语义。

### 7.5 tests 与 docs

- 先做坏数据只读扫描；有坏数据时迁移必须失败。
- PostgreSQL 反例测试直接尝试写跨 App、非法状态形状、重复身份绑定、孤儿策略和计数越界。
- 并发测试覆盖两个授权变更、模板编辑与计划确认、WebAuthn 两次认证、通知同幂等键不同字段。
- 在项目上线基线前压平或重建迁移；需要保留的数据走独立显式导出/导入，不让历史迁移静默删除。
- 中文领域文档包含修订、命令前置条件、状态真值表、关系所有权和迁移失败规则。

### 7.6 完成证据

- 已批准申请不能作用于审批后产生的新授权修订；
- 同一时点、同一授权在提交校验、审批展示和最终落地得到完全相同的有效成员集合；
- 模板编辑后，旧计划仍严格按绑定修订执行，或因明确前置条件失败而冲突；
- 数据库直接拒绝全部已定义非法状态和跨 App 组合；
- 重复钉钉身份绑定和孤儿策略在迁移前被发现，未被 `.first()` 或默认父对象掩盖；
- 从 PostgreSQL 空库迁移到最新成功；携带非法或需保留数据的升级路径按设计明确失败或完整保留；
- API、前端、测试和中文文档不再出现缺修订兼容路径。

## 8. 第 4 波：严格 API、能力模型和前端读写一致性

关联登记项：`EA-AUD-015`、`EA-AUD-018`—`EA-AUD-021`、`EA-AUD-027`

### 8.1 schema 与 API

- 请求、成功响应、错误响应、分页和封闭枚举建立唯一权威 schema。
- 非分页列表与分页列表使用不同必填信封；2xx JSON、204、文本和下载由端点显式声明。
- 查询参数只有“缺失”可使用默认值；显式格式错误、越界或非法枚举统一返回结构化 422。
- 连接器映射重复键、损坏的非对象配置、运维筛选任意字符串和与状态无关的多余字段必须在
  权威 schema 边界失败；不得去重、置空或忽略。
- 错误信封采用稳定 `code`、`field_errors`、安全参数和诊断编号；原始异常、Pydantic input、
  JSON 路径和 secret 不进入用户响应。
- 状态映射必须穷尽；未知值在网络边界失败并进入区块契约错误态。

### 8.2 领域层与能力

- 后端返回基于当前 actor 和实体状态计算的能力/允许动作，而不是只返回角色名称。
- Console 能力至少区分进入工作区、目录写入、成员管理、连接器管理、全局设置和运维动作。
- 门户申请动作由申请状态机提供：四类申请、撤回、允许审批动作和冲突语义使用同一来源。
- 交接删除、授权组停用/恢复和连接器映射编辑均由同一能力与实体状态事实决定；不能只用角色名
  或页面位置推断动作可用性。
- OIDC 登录、凭据签发、紧急撤权、审批复合结果、手动对账和交接确认分别定义“完成、未变更、
  部分完成、依赖失败”的机器状态；未取得权威事实时禁止返回成功或允许继续。
- 建立“命令 → 受影响读模型”矩阵，覆盖应用详情、应用列表、配置就绪度、成员、凭据、权限、
  授权组和目录版本。

### 8.3 前端

- `apiRequest` 必须接收端点 decoder；删除 `itemsFromPayload` 空数组兜底和泛型强制断言收尾。
- 侧栏、路由、页签和按钮消费服务端能力；无权深链显示明确无权限页。
- `change`、`revoke`、`renew` 从当前授权事实启动；撤回只在权威动作允许时显示。
- mutation 成功后按影响矩阵更新或失效全部读模型，不按组件局部猜测。
- 并发查询只允许与最新变量快照匹配的响应更新结果；删除最后一页唯一行后页码必须收敛。
- 401 进入壳层单一重新认证状态；403 保持权限错误，不跳登录。
- 失败反馈按字段、对话框、区块、行级或后台轮询选择一个主载体；不增加全局无条件 Toast。

### 8.4 tests 与 docs

- 契约样例、后端 serializer、SDK、前端 decoder 和 API 文档使用同一成功/错误结构。
- 畸形 200、非 JSON 2xx、未知枚举、非法分页/筛选和字段错误必须进入失败态。
- 角色矩阵覆盖 anonymous、普通员工、developer、owner、superuser 的页面和 API。
- 反例覆盖重复连接器映射、损坏配置、非法运维分区、空 scope 坏数据、超长审批意见和旧查询
  响应晚到；所有反例都必须进入明确失败态。
- 使用至少 101 个 App 验证资源选择器分页；四类申请和七个状态必须穷尽测试。
- 用真实 `QueryClient` 验证每个命令对全部派生读模型的失效。

### 8.5 完成证据

- `{items: [...]}`、缺失 `data`、错误 `pagination`、未知状态和非 JSON 2xx 都不能显示正常空态或
  成功；
- 非超级管理员看不到系统管理入口，owner/developer 只看到后端允许的操作；
- 第 101 个及之后的 App 可通过分页/搜索选择；
- 四类申请和撤回均能从正式门户产生正确 payload；
- 停用主体登录、停用 App 凭据签发、零变更紧急撤权、`queued=false` 对账、审批已决定但授权
  未落地、交接明细缺失均不会显示完整成功或允许流程继续；
- 不可删除的交接任务不展示删除动作；停用授权组仍有明确恢复入口；连接器映射写入与后端能力
  完全一致；
- 成员、凭据、权限或授权组变化后，应用详情、列表和配置就绪度立即一致；
- 英文和中文界面均只展示由稳定 code 本地化的用户文案。

## 9. 第 5 波：出站网络、秘密生命周期与隐私保留

关联登记项：`EA-AUD-012`、`EA-AUD-016`、`EA-AUD-017`、`EA-AUD-025`—`EA-AUD-027`

### 9.1 网络边界

- 自动接入复用固定已验证 IP 的 HTTPS 传输，保留原 host 用于 SNI 和证书验证。
- 默认禁止重定向；若业务必须支持，逐跳重新验证 scheme、host、全部 IP、跳数和响应上限。
- 目录、OIDC、DingTalk、Webhook 和连接器统一使用分块大小上限、单调时钟总 deadline 和完整
  传输异常分类。
- DNS 使用有界、可监督的 resolver 资源；队列满时明确拒绝，不创建无界遗留线程。

### 9.2 秘密与响应

- secret 输入使用安全类型和隐藏 input 的验证错误。
- TOTP seed、一次性 token、OAuth secret 的成功和失败响应统一设置
  `Cache-Control: no-store, private`。
- 前端提交 secret 后立即清除输入、mutation variables、错误对象和缓存；诊断日志不记录原文。
- 审计只记录稳定错误 code、依赖标识和诊断编号。

### 9.3 保留与最小化

- 按数据集确定最短/最长保留期、法定保留例外、备份过期和删除传播。
- Stream 成功处理后清除原始正文，只保留幂等身份、状态和摘要。
- Webhook 正文只保留至重试窗口结束。
- 离职画像保留稳定身份和审计引用，清除不再需要的联系方式与头像等资料。
- 审计 metadata 使用字段白名单，并通过定时分批任务执行保留策略。
- 离职画像、审计/健康历史、Stream 和 Webhook 分别建立关闭记录；共享保留矩阵不代表共享
  清理实现，也不允许用一个数据集的验证替代另一个。

### 9.4 完成证据

- DNS 两次返回不同地址、公网重定向私网、超大响应、body 阶段超时和 Unicode URL 都产生安全、
  类型化失败，不访问内网且不悬空任务；
- 错误响应不包含提交 secret 的足够长子串；
- 浏览器后退、缓存检查和响应头测试不能恢复 TOTP 或一次性凭据；
- 定时清理具有批次、幂等、审计、容量指标和备份传播验证；
- 中文保留政策与实现的数据集、字段和定时任务一一对应。

## 10. 第 6 波：性能、可观察性与运维完整性

关联登记项：`EA-AUD-025`、`EA-AUD-029`、`EA-AUD-031`

### 10.1 数据访问

- App readiness、授权组、模板、团队、目录、审批恢复和健康快照使用批量预取、数据库聚合或分页。
- GET 不逐行开启写锁事务；恢复动作移入集合式命令或后台任务。
- 过期授权、健康历史和保留清理采用稳定游标、有限批次、总时限和单实例协调。
- `direct_grants` 等集合在 API 和 domain 双层设相同硬上限，批量校验后再写入。

### 10.2 远端读取与缓存

- Web 请求不直接执行 30 秒全量外部组拉取；后台刷新本地快照，GET 只读分页结果。
- OIDC JWKS 按 issuer/JWKS URL 缓存，`kid` 未命中只 single-flight 刷新一次。
- 目录同步先比较轻量 generation，再拉取变化数据。

### 10.3 运维与构建

- PostgreSQL、Redis 和应用 readiness 使用真实健康门禁；公网 liveness 只返回固定整体状态。
- PR 与发布作业拆分最小权限，第三方 Action 固定完整 commit SHA。
- 固定 Node、pnpm、Python 和 uv 口径；修复 ASGI 文档或删除未支持路径。
- 统一 `.env.local` 解析器。
- 路由分包并建立主包/关键分包预算；性能结论以实际设备和网络测量为准。

### 10.4 完成证据

- 使用 PostgreSQL `EXPLAIN (ANALYZE, BUFFERS)` 和代表性基数记录整改前后查询数、扫描行和延迟；
- 最大页 App、授权组和团队列表没有按行/按 grant N+1；
- 积压任务在固定批次内完成，不与下一轮重叠；
- 外部组页面响应时间不再受远端 30 秒 deadline 直接控制；
- 健康快照查询只读取每类最新记录，历史保留任务可观测；
- 构建预算超限会阻断 CI，但预算来自实测而不是任意复制 500 kB 告警值。

## 11. 第 7 波：反馈、国际化、响应式和无障碍

关联登记项：`EA-AUD-027`—`EA-AUD-029`

### 11.1 反馈与国际化

- 先完成第 4 波稳定错误 code，再移除页面对 `error.message`、`last_error` 和原始枚举的直接展示。
- 字段错误在控件旁，提交错误在对话框，查询错误在区块，行级动作使用带上下文的单一反馈，
  后台轮询只显示陈旧警告。
- 成功反馈按动作风险和状态变化可见性选择 Toast、按钮旁“已保存”或持久结果；不统一强制 Toast。
- Django 登录、安全和错误页进入双语范围；密码最小长度和 HTML 属性来自同一后端策略事实。
- 消息护栏自动发现全部生产组件，同时检查硬编码中文和英文用户文案。
- 员工门户以业务名称、来源和有效期为主，不把 key、版本和 JSON 路径作为主信息。

### 11.2 响应式与无障碍

- `PageHeader` 在窄屏改为纵向/换行动作布局，删除用全局横向裁剪掩盖错误的做法。
- 表格建立明确最小宽度或移动摘要结构；可滚动区域保持可发现和键盘可达。
- 重新定义通过 WCAG AA 的文本、状态和焦点 token。
- `UserSelect` 采用单一 combobox 模式；Tabs 使用 roving tabindex；Menu/Popover 实现完整键盘、
  焦点和 ARIA 关系。
- 动态 Banner 由调用方显式选择 `alert`、`status` 或关闭；图标按钮保证命中区。
- `Button loading` 提供 `aria-busy` 和非运动加载文本。
- 不实施被复核驳回的强制 Dialog、Toast、Tab 或步骤装饰性动画。

### 11.3 tests 与 docs

- 在 320、390、768、900px 测量真实矩形、裁剪、滚动宽度和关键操作可见性。
- 区分源码契约、无障碍树、自动扫描和真实辅助技术测试。
- 颜色测试记录前景、背景、字号和计算值。
- 至少对登录壳、门户申请、控制台应用页和关键对话框建立稳定截图或明确命名的布局冒烟。
- 中文术语表、英文消息和 API 错误码文档同步更新。

### 11.4 完成证据

- 两种语言遍历一级导航、工作区、弹窗、空态、错误态、分页和 `aria-label` 时无非专有名词串语；
- 密码页面提示、`minlength` 和后端 validator 完全一致；
- 390px 下页头主操作可见，多列表格不逐字压缩；
- 组合框、Tabs、Menu 可用键盘完成并通过无障碍树/辅助技术抽查；
- 每个失败场景只有一个主反馈载体，401 只出现一次重新登录提示；
- `prefers-reduced-motion: reduce` 下所有状态仍能通过文字、语义和焦点理解。

## 12. 第 8 波：删除兼容残留并重构架构热点

关联登记项：`EA-AUD-030`、`EA-AUD-032`、`EA-AUD-033`

### 12.1 低风险删除

- 删除确认无调用的旧权限模板处理器、旧内存分页、兼容再导出、孤立常量、测试 helper、历史前端
  类型和 `blocked` 分支。
- 只收窄未消费 export，不删除仍在文件内部使用的实现。
- `applications.models` 中的跨文件导入同时承担 Django 模型注册，必须先设计显式注册或重组，
  不能机械删除。
- 运行中的 Vite manifest 和散列资源只能“清理后立即重建”，不能按缓存随手删除。

### 12.2 领域边界重构

- 交接预览改为“短事务生成代次—事务外 HTTP—条件提交”，不跨网络持锁。
- 授权领域只写通用事务事件，不导入具体连接器；Outbox 持久化仍与授权事务同成同败。
- CRM seed 只调用规范 manifest 导入和正式领域服务，删除平行 `_upsert_manifest_*`。
- 通知和生命周期模块按已建立的聚合、状态机和适配器边界拆分；不保留旧总模块转发层。
- 前端交接向导和申请表单以判别状态机、纯领域选择模型和端点契约模块重构。

### 12.3 完成证据

- 全仓精确搜索证明被删除符号无内部调用；公开 SDK/管理命令另有外部契约清单证明；
- Django app registry、Celery task、management command、pytest fixture 等动态入口均有专门
  测试，未被静态零引用误删；
- CRM seed 与正式 manifest 输入产生相同目录版本、哈希、停用和审计事实；
- 交接预览慢 30 秒时不持有数据库行锁，旧响应因代次不匹配明确冲突；
- 新模块调用方全部迁移，旧 import、旧 facade、旧类型和转发层为零；
- 前后端全量构建、测试、服务重启和真实 HTTP 验证完成。

## 14. 最终退出标准

只有同时满足以下条件，才可认为本轮整改完成：

1. 全部 P0/P1，即 `EA-AUD-001`—`EA-AUD-016`、`EA-AUD-018`—`EA-AUD-024`，均有关闭
   证据；条件项若保留，必须有明确外部契约或已接受风险决定，不能以“暂时没复现”关闭。
2. 唯一生产路径使用 PostgreSQL、正式服务器、不可变签名镜像、最小 secrets 和强制安全设置。
3. 本地管理员与 OIDC 管理员旧会话能够按权威变化撤销。
4. 所有关键异步动作都有租约、fencing、watchdog、幂等和可恢复终态。
5. 授权申请、模板计划和 WebAuthn 使用可执行的修订/并发不变量。
6. PostgreSQL 直接拒绝已定义的非法状态和跨应用关系。
7. API 不再对非法输入、畸形响应、未知枚举或依赖失败静默默认。
8. 前端只展示权威能力，写后所有受影响读模型一致，错误与成功反馈真实。
9. CI 强制执行主后端、PostgreSQL、SDK/FastAPI、静态检查、前端构建/Vitest 和真实全栈关键
   链路；没有未白名单 skip。
10. 数据保留、秘密响应、出站网络和详细健康信息具有明确安全边界。
11. 中文与英文、响应式和无障碍关键路径通过真实页面验收。
12. 所有文档只描述当前唯一实现，不保留旧字段、旧状态、兼容入口或已经失效的部署口径。

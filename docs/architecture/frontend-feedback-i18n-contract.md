# 前端反馈与国际化契约

本文记录管理控制台与员工门户的用户反馈、错误本地化和局部状态边界。

## 网络边界

- 浏览器 API 请求只把结构化 JSON 成功响应视为成功。除显式无正文的 `204` 外，`2xx` 非 JSON、损坏 JSON 或列表信封缺少 `data` 都必须快速失败。
- 网络失败使用稳定错误码 `NETWORK_ERROR`；成功响应格式异常使用 `UNEXPECTED_RESPONSE_TYPE` 或 `INVALID_JSON_RESPONSE`；列表信封异常使用 `LIST_PAYLOAD_CONTRACT_ERROR`。
- 后端 `401` 是全局会话失效事件，不是普通业务错误。网络层发布 `easyauth:api-session-expired`，壳层只应展示一次重新登录恢复入口。
- 后端原始异常、HTML 错误页、JSON 字段路径和内部枚举不得直接作为用户主文案展示；这些内容只可进入日志、诊断编号或受控技术详情。

## 用户反馈

- 失败必须在用户当前操作上下文可见。字段错误使用字段级提示；对话框提交错误留在对话框；区块数据加载失败使用区块错误；后台轮询失败使用区块陈旧警告。
- 成功反馈按动作风险和界面变化选择单一载体。状态徽标、行消失、按钮旁“已保存”或 toast 均可作为成功反馈；不得为所有 mutation 机械增加成功 toast。
- 异步操作只有在真实完成后才能显示成功。剪贴板复制必须等待 `navigator.clipboard.writeText` 成功；任务触发必须读取返回的机器状态，例如 `queued=false` 应显示“已合并”而不是“已入队”。
- 并发请求必须使用提交时快照和最新请求门禁，旧响应不得覆盖新输入对应的结果。

## 国际化

- 用户可见文本、`aria-label`、placeholder、toast、错误标题、按钮内状态和空态都必须来自消息目录或明确的本地化函数。
- API 错误展示优先依据稳定 `code` 和结构化参数在前端翻译。后端自然语言只能作为临时安全摘要，不得成为唯一契约。
- 浏览器拒绝 `localStorage` 访问时，语言状态继续以内存值生效；持久化失败不得造成白屏或中断语言切换。

## 验收

- 模拟非 JSON `2xx`、损坏 JSON、网络失败、`401`、畸形列表信封、剪贴板拒绝、用户搜索失败和重复提交，页面不得出现假成功、假空态或旧响应覆盖。
- English 模式下共享控件的复制、分页、下拉错误、会话失效和安全设置错误不得出现非必要中文。
- 简体中文模式下不得展示 Python/Django/Pydantic 异常、JSON 字段路径或未解释的内部协议枚举。

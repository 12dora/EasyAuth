# EA-AUD-015 完成与失败语义

## 目标

EA-AUD-015 用统一口径约束后端在关键状态转换中的完成、失败和依赖不可用语义。任何没有真实完成业务动作的请求都不得返回成功；任何缺少上游事实、目录事实或本地状态前置条件的流程都必须显式失败，并保留可诊断信息。

## 语义边界

- OIDC 回调只允许活跃本地用户写入认证会话。若本地 `UserMirror.status` 不是 `active`，回调返回 `403`，只清理 OIDC 尝试态，不写入登录会话。
- 静态 token 创建和轮换必须在事务内重新锁定并读取 `App`。若应用已停用，接口返回 `409 CONFLICT`，不生成 secret，不写入 credential。
- 紧急撤权必须真实撤销一条当前有效授权。若目标用户和应用存在但没有当前有效授权，接口返回 `409 CONFLICT`，不记录成功审计。
- 审批通过后的应用授权落地若失败，接口返回 `422 SEMANTIC_VALIDATION_ERROR`，响应必须同时说明审批决策已提交，并返回最新审批请求快照，避免前端误判为未决状态。
- 托管用户预览遇到 Authentik 目录错误或本地目录快照过期时返回 `503 DEPENDENCY_UNAVAILABLE`，不得用空列表或旧数据伪装成功。
- 钉钉目录同步只在所有组织上下文拉取成功后推进 generation。任一用户组织上下文失败时，同步整体以依赖不可用失败结束，不写入部分成功快照。
- 依赖健康检查必须覆盖 connectors 核心依赖。Authentik 目录健康必须包含与运行配置一致的 source、非空 sync、唯一 corp、成功状态、有效 generation 和用户/部门计数。
- 钉钉工作通知回执查询必须使用严格 DTO。缺少必需回执字段、字段类型错误或依赖查询失败时，只记录收件人 `error`，不得更新 `last_reconciled_at`；只有成功取得合法回执后才能标记已对账。
- 前端 API 解码器遇到 `2xx` 非 JSON 响应时必须抛出 `UNEXPECTED_RESPONSE_TYPE`，不得把空正文或文本正文当作成功 payload。

## 验证要求

- 后端变更必须覆盖单元测试、集成测试、`manage.py check`、迁移检查、Ruff 和 basedpyright。
- 前端解码器变更必须覆盖 `api.test.ts`，并通过前端构建。
- 修改影响运行中页面响应的后端代码后，必须重启独立 Django 开发服务，并用真实 HTTP 响应确认新代码已加载。
